# Kairos autotrader: руководство оператора

Описание репозитория и правила разработки — в `README.md` (на английском, как во всех репозиториях Kairos).

Тонкий запускатор: сам сканирует рынок, спрашивает нейросеть, ставит заявки на EVEDEX со стопом и тейком,
ведёт позиции и считает результат. До трёх позиций одновременно, не больше одной на инструмент, плечо 1x.

## Как он принимает решение

1. Каждые 15 минут (`scan_minutes`) берёт публичные закрытые минутные свечи Binance (бессрочные
   контракты USD-M) по инструментам из конфига: для `SOLUSD` это `SOLUSDT`. Так задумано в схеме Kairos:
   сигнал считается по Binance, заявка ставится на EVEDEX. Каждую страницу свечей проверяет разборщик
   Quant Scouts: страница с пропуском или неполная не принимается, и по этому инструменту в этот скан
   сигнала не будет. Свечи хранятся в папке `closed-bars` рядом с журналом. Первый запуск скачивает
   три недели истории, это около полутора минут; дальше докачиваются только новые минуты, а пять
   последних сохранённых перепроверяются.
   Правила по-прежнему читают часовые свечи: часовая свеча пересобирается так, чтобы закрываться
   в :00, :15, :30 и :45. Рынок просматривается вчетверо чаще без перехода на более короткие и дорогие
   по комиссиям свечи.
2. Сигналы ищет Strategy Engine системы Kairos (репозиторий `kairos-strategy-engine`, пакет
   `kairos_strategy.hourly_trend`): откат к средней по тренду 4ч или пробой 20-часового экстремума.
   Движок выдаёт сигнал в виде контракта системы `StrategyIntentV1`: в нём сторона, стоп, цель, срок
   и отпечатки кода правил и каждой из 30 240 прочитанных свечей. Запускатель сверяет, что сигнал
   объявил ровно те свечи, что лежат в его кэше. Своей копии правил у запускателя нет. Если движок
   недоступен или его код отличается от закреплённого, новые сделки не открываются, открытые
   позиции ведутся как обычно.
   Затем сигнал получает маршрут настоящего Router (`CandidateRouteV1`): обычный обзор или «конфликт»,
   если свежие новости спорят со стороной сделки, и срок обзора (`review_timeout_s`, не больше 60 секунд).
   Сигнал старше двух минут Router отбрасывает.
3. Нейросеть получает по каждому инструменту показатели графика, ставку финансирования, открытый интерес,
   объём за сутки, положение цены в недельном диапазоне; индекс страха и жадности; сигналы слоя новостей
   Text Scouts; решение Macro Strategist; открытые позиции и результаты последних сделок самой системы;
   историческую долю выигрышных сигналов. По каждому сигналу она выносит вердикт ALLOW или VETO
   и вероятность успеха. Менять стоп, размер или придумать свою сделку она не может. Ответ со ссылкой
   на несуществующий сигнал превращается в WAIT. Сырые заголовки новостей модель не получает: только
   проверенные сигналы Text Scouts.
4. Торгуются разрешённые сигналы с вероятностью не ниже `min_confidence`, лучшие первыми, пока есть
   свободные места.
5. Размер считается так, чтобы срабатывание стопа с комиссиями стоило не больше `risk_per_trade_usd`,
   а позиция занимала не больше равной доли капитала.
6. Вход рыночной заявкой IOC; стоп и тейк уходят на биржу в той же заявке. Стоп и тейк берутся
   из контракта сигнала как есть, то есть в ценах Binance. Вход пропускается, если спред шире
   `max_spread_bps`, если цена EVEDEX ушла от цены сигнала (эта же проверка ограничивает расхождение
   двух бирж) или если истёк срок сигнала (15 минут после закрытия свечи).

## Рамки

| Что | По умолчанию | Потолок в коде |
| --- | --- | --- |
| Капитал для расчёта | 100 USDT | 100 |
| Риск на сделку | 0,25 USDT | 1 |
| Позиций одновременно | 3 | 3 |
| Остановка входов при убытке сессии | 5 USDT | 10 |
| Сделок в день | 12 | 12 |
| Плечо | 1x | 1x |

В боевом режиме сначала разрешена одна позиция. Три места открываются после первой сделки, прошедшей
полный круг на бирже: вход, стоп и тейк приняты, выход, учёт.

BTC и ETH остаются в списке как фон для нейросети: их минимальный лот (около 74 и 20 USDT) при риске
0,25 USDT на сделку обычно не проходит. Чтобы они торговались, нужен больший `risk_per_trade_usd`.

Кода вывода средств и переводов в программе нет.

## Запуск двойным щелчком

- `check-account.cmd` — проверка без заявок: рынок, подпись, доступ к счёту.
- `start-live.cmd` — боевой режим. При сбое сам перезапускается через 30 секунд.
- `report.cmd` — отчёт по боевой папке.

В этих файлах записаны путь к файлу ключей и номера строк (9 — ключ биржи, 6 — ключ кошелька).
Самих ключей в них нет.

## Команды

Python: собственное окружение репозитория, создаётся командой `uv sync --locked` (папка `.venv`).
Файл `start-live.cmd` пока запускает прежнее окружение
`D:/Kairos/runtime/evedex-coherent-launchcheck-20261109/.venv`; его переключат при остановленной торговле.
Запускать из папки `D:/Kairos/kairos-autotrader`.

Проверка без заявок:

```
python -m kairos_autotrader check --keys-file <файл ключей> --api-key-line 9 --wallet-key-line 6
```

Один скан рынка без заявок:

```
python -m kairos_autotrader scan --no-llm
```

Бумажный режим (настоящие котировки, ненастоящие сделки):

```
python -m kairos_autotrader run --mode paper --runtime-dir D:/Kairos/runtime/autotrader-paper --keys-file <файл ключей>
```

Боевой режим (настоящие заявки):

```
python -m kairos_autotrader run --mode live --confirm-real-orders --runtime-dir D:/Kairos/runtime/autotrader-live --keys-file <файл ключей> --api-key-line 9 --wallet-key-line 6
```

Отчёт; с `--outcomes` ещё и сравнение «нейросеть разрешила / отклонила / алгоритм без нейросети»:

```
python -m kairos_autotrader report --runtime-dir D:/Kairos/runtime/autotrader-live --outcomes
```

Ключ OpenAI находится в файле ключей сам, по подписи строки со словом `openai`.
Флаг `--no-llm` отключает нейросеть: решает только алгоритм. Полезно для сравнения.
Свои настройки: скопировать `config.example.json` в `config.json` и добавить `--config config.json`.

## Управление

- Файл `STOP` в папке запуска: новых входов нет; после закрытия всех позиций программа выходит.
- Файл `CLOSE`: закрыть все позиции сейчас и больше не входить.
- Ctrl+C останавливает программу, но не закрывает позиции: стопы и тейки остаются на бирже.
  При следующем запуске программа подхватит позиции.
- Если входы остановлены (`halted`), причина записана в `state.json` и `journal.jsonl`.
  Снять остановку и начать новую сессию: флаг `--new-session`.

## Учёт результата

Если позиция всё время была единственной, её результат равен изменению баланса на бирже: это точная цифра.
Если позиции пересекались, результат каждой считается по ценам входа и выхода и комиссии и помечается
в отчёте как оценка. Итог сессии всегда сверяется с балансом биржи.

## Что проверено и что нет

Проверено тестами: 105 тестов с имитацией биржи; подпись заявок совпадает с официальным SDK байт в байт;
формат заявок сверен со спецификацией `exchange-api.evedex.com/api/openapi.json`. Проходят проверки проекта:
Ruff, mypy, Bandit, сборка пакета.

Проверено в бою 11.11.2026:

- биржа приняла рыночную заявку со стопом и тейком (сеть подписи 42161, сторона стопа равна стороне позиции);
- первая сделка прошла полный круг: вход, защита на бирже, выход, учёт по балансу;
- модель ответила во всех ролях: оценка сигналов, Text Scouts, обзор Aggregator, Macro Strategist;
- Risk Manager посчитал размеры по решению Macro.

Не проверено: закрытие позиции самой программой по сроку или по её собственному стопу, поведение при
частичном исполнении, длительная работа без присмотра.

Если биржа не примет стоп, программа сразу закроет позицию и остановит входы.

## Про прибыльность

Замер 12.11.2026 на 36 днях минутных свечей EVEDEX, 10 инструментов, с комиссиями и проскальзыванием,
без нейросети (R — один риск на сделку):

| Скан | Сигналов | В день | Средний результат |
| --- | --- | --- | --- |
| раз в час | 495 | 15 | −0,08 R ± 0,05 |
| каждые 15 минут | 2009 | 62 | −0,08 R ± 0,03 |

Сигналов вчетверо больше, средний результат тот же: без отбора правила слегка убыточны. Сигналы
на соседних сканах и по разным монетам зависят друг от друга, поэтому настоящая погрешность больше
указанной. Зарабатывает ли связка с отбором нейросетью, покажет только `report --outcomes` после
нескольких десятков сделок.

### Сигнал по свечам Binance или по свечам EVEDEX

По схеме Kairos сигнал считается на минутных свечах Binance, а заявка ставится на EVEDEX. До версии
0.5.0 запускатель считал сигнал на свечах самой EVEDEX, с версии 0.5.0 — на свечах Binance. Замер
12.11.2026 перед переходом (36 дней, 10 инструментов, те же правила, результат каждой сделки считается
по свечам EVEDEX с комиссиями):

| Откуда свечи для сигнала | Сигналов | Средний результат |
| --- | --- | --- |
| EVEDEX (до 0.5.0) | 2142 | −0,08 R ± 0,02 |
| Binance (как в схеме, с 0.5.0) | 2167 | −0,05 R ± 0,02 |

93% сигналов совпадают, цены бирж расходятся в среднем на одну десятитысячную. Разница результатов
меньше погрешности: источник свечей прибыльности не меняет.

## Настоящий Strategy Engine системы Kairos

Автотрейдер умеет запускать настоящий движок стратегий из репозитория `kairos-strategy-engine`
без изменений его кода: движок работает в собственном окружении отдельным процессом, получает закрытые
минутные свечи EVEDEX и возвращает свои намерения (сторона, стоп, цель, срок).

- `engine-replay.cmd` — замер стратегий движка на 45 днях истории, с комиссиями. Без заявок и ключей.
  Боевые правила считаются как в торговле: сигнал по свечам Binance, результат по свечам EVEDEX.
- `start-shadow.cmd` — теневой режим: раз в 5 минут записывает новые сигналы движка в
  `D:\Kairos\runtime\engine-shadow`. Без заявок и ключей.
- `report-shadow.cmd` — что стало бы с каждым записанным сигналом.

Запускаются четыре стратегии, которым хватает цен и объёмов: `trend_pullback_reclaim_v1`,
`range_mean_reversion_v1`, `right_tail_trend_v1`, `regime_aligned_right_tail_v1`. Остальным нужны данные,
которых EVEDEX не отдаёт (объём покупок по рынку, история финансирования), либо они выдают доли портфеля.

Эти четыре стратегии только наблюдают: в боевую торговлю идут сигналы пакета `hourly_trend`
того же движка (в таблице ниже — «правила автотрейдера»). Замер на 11.11.2026
(45 дней, 10 инструментов, R = один риск на сделку, после комиссий):

| Стратегия | Сигналов | Средний результат | Комиссии на сделку |
| --- | --- | --- | --- |
| `trend_pullback_reclaim_v1` | 307 | −0,50 R ± 0,08 | 0,44 R |
| `range_mean_reversion_v1` | 1683 | −0,91 R ± 0,03 | 0,90 R |
| `right_tail_trend_v1` | 113 | −0,06 R ± 0,16 | 0,07 R |
| `regime_aligned_right_tail_v1` | 14 | +0,45 R ± 0,50 | 0,07 R |
| правила автотрейдера (1 час) | 571 | −0,08 R ± 0,05 | 0,15 R |

Сигналы по разным монетам приходят одновременно и зависят друг от друга, поэтому настоящая погрешность
больше указанной.

## Настоящий слой новостей Text Scouts системы Kairos

Раз в 5 минут программа запускает конвейер из репозитория `kairos-text-scouts` без изменений его кода:
официальные источники (GDELT и шесть RSS-лент) → очистка → только новости моложе 30 минут → удаление
повторов → отбор значимых (не больше пяти за раз). Отобранное уходит модели с инструкцией самого Text Scouts,
а ответ проверяется его же правилами и превращается в сигналы: тема, направление (в плюс или в минус
для крипторынка), уверенность, источники. Сигналы за последние 6 часов получает нейросеть, оценивающая сделки.

- Сделок слой не создаёт и сторону не выбирает: это только доказательства для оценки.
- Без ключа модели или при её сбое работает грубая оценка по ключевым словам; такие сигналы помечены.
- X и Reddit выключены: для них нужны отдельные ключи, которых в проекте нет.
- GDELT ограничивает частоту запросов и может отвечать отказом; тогда в журнале у него 0 новостей,
  а слой работает на RSS.
- Сбой слоя новостей торговлю не останавливает и не задерживает: он опрашивается отдельно.
- Настройки: `use_text_scouts`, `news_poll_minutes`, `max_news_llm_calls_per_day`.

Проверить без ключа, что слой видит сейчас:

```
python -m kairos_autotrader news
```

## Плечо

Биржа хранит плечо отдельно для каждого инструмента и отклоняет заявку с другим значением. Программа
торгует только с плечом 1x: получив такой отказ, она ставит для этого инструмента 1x на счёте и отправляет
заявку ещё раз. Это меняет настройку плеча инструмента на бирже.

## Настоящий обзор сигналов: Router и Aggregator системы Kairos

Маршрут Router получает каждый сигнал (см. шаг 2 выше). Обзор по правилам Aggregator — кодом
репозитория `kairos-aggregator` без изменений:

1. Router решает, спорят ли свежие новости со стороной сделки. Считаются сигналы Text Scouts не старше
   10 минут до закрытия свечи с уверенностью от 0,25; при споре обзор помечается CONFLICT и идёт
   с глубоким рассуждением.
2. Модель получает инструкцию самого Aggregator и по каждому сигналу отдельно отвечает: ALLOW, VETO или
   DEFER, приоритет 0–100 и коды причин.
3. Ответ проверяется схемой Aggregator. Любое отклонение (лишнее поле, попытка сменить сторону, сбой модели)
   превращается в DEFER. Если при споре с сильными новостями модель всё же ответила ALLOW, правило Aggregator
   заменяет это на DEFER.

Сигнал и маршрут — настоящие контракты системы (`StrategyIntentV1`, `CandidateRouteV1`). Контекст
обзора пока собирается в собственной форме, а не как `DecisionContextV1`, и модель вызывается напрямую,
а не через шлюз `kairos-llm`: это следующий шаг (2b в `docs/ALIGNMENT.md`). Для него нужна правка
в самом Aggregator: его текущий код вставляет в запрос к модели все 30 240 отпечатков свечей сигнала,
около 2 МБ, и модель такой запрос не примет.

На живых данных за 30 сканов инструкция Aggregator ответила ALLOW 3 раза, VETO 15 и DEFER 90 раз.
Если сделать этот обзор решающим (`review_mode: "aggregator"`), сделок будет заметно меньше.

Кто открывает сделки, задаёт `review_mode`:

- `"probability"` (по умолчанию) — прежняя оценка: один вызов на все сигналы, вероятность и порог
  `min_confidence`.
- `"aggregator"` — обзор Router и Aggregator: сделки открываются по ALLOW в порядке приоритета, порога нет.

При `review_shadow: true` второй способ тоже вызывается и только записывается в журнал. Отчёт
(`report.cmd`) показывает, что стало бы с сигналами, которые Aggregator разрешил, отклонил и отложил.
Обзор Aggregator делает один вызов модели на каждый сигнал, поэтому расход на модель в этом режиме
в несколько раз выше.

## Настоящие Macro Strategist и Risk Manager системы Kairos

**Macro Strategist** (`kairos-macro-strategist`). Раз в сутки и после обвала (падение инструмента на 10% за час,
не чаще раза в час) модель получает инструкцию самого Macro Strategist и сводку: счёт, результаты, показатели
рынка. Она возвращает стратегическое решение: режим рынка (BULL, BEAR или CHOP), долю капитала в резерве,
долю на каждую стратегию и потолок плеча. Ответ проверяется схемой Macro Strategist; при любом сбое действует
его защитное решение: CHOP и весь капитал в резерве. Макроэкономических и ончейн-данных в сводке нет, и там
прямо сказано, что они недоступны. Решение получают оба обзора сигналов и Risk Manager.

**Risk Manager** (`kairos-risk-manager`). Каждый сигнал проходит его правила:

- режим CHOP запрещает любые входы, BEAR запрещает покупки, BULL запрещает продажи;
- стратегия без доли в решении Macro не торгует; решение старше 26 часов недействительно;
- риск на сделку 0,25% счёта, суммарный открытый риск не больше 1% счёта;
- дневная просадка 3% останавливает новые входы;
- размер считается по убытку на стопе с комиссией и проскальзыванием и ограничен резервом, долей стратегии
  и объёмом на лучшей цене стакана.

Проверка счёта написана по тем же формулам и настройкам заново: исходная требует снимок счёта, который бывает
только у тестового счёта на тестовой бирже. Три запрета, существующие только для тестового профиля (список
одобренных стратегий, только тестовая биржа, только тестовый счёт), не применяются.

Кто допускает вход, задаёт `risk_mode`:

- `"autotrader"` (по умолчанию) — собственный расчёт программы; Risk Manager оценивает каждый сигнал
  и только записывается (`risk_shadow`).
- `"kairos"` — вход возможен только с одобрения Risk Manager, размер берётся меньший из двух. Если Macro
  не дал решения или сказал CHOP, входов не будет.

**Router** (`kairos-router`), дополнительно к классификации спора с новостями: сигнал старше 120 секунд обзор
